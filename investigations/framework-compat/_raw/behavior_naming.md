# Behavioral fidelity: naming

Spec test: `/home/frappe/benches/bench-cpython314/apps/frappe/frappe/tests/test_naming.py` (class `TestNaming`)
Reference impl: `/home/frappe/benches/bench-cpython314/apps/frappe/frappe/model/naming.py`
ferro impl: `/home/frappe/ferro/src/naming.rs` (entry `resolve_name`, called from `orm.rs:568`), child rows in `orm.rs:677` `insert_children`, helpers in `util.rs`.

Judgment rubric for this domain: **1:1** — naming is a core contract ferro explicitly reimplements (`naming.rs` docstring says so: "ferro must follow the SAME rules so names are identical … AND so the persistent `tabSeries` counters stay in sync"). So most behaviors are MUST-match. A few sub-functions (revert on rollback, append-number-on-rename, custom hooks) are arguably "somewhat" given footprint goals, but they are noted as GAPs because the deliverable claims series-fidelity.

All HTTP probes below were run against the live pure-Rust server at `http://127.0.0.1:8081` (site `bench-test/mysite.sqlite`), token `f0234ffaf8:...` provisioned for Administrator.

## naming

### Behaviors Frappe guarantees (from the spec test + naming.py)
1. **`field:<f>` autoname** — name = stripped `cstr(doc.<f>)`; empty → throw `<label> is required` (`test_child_table_naming`, `_field_autoname`).
2. **field-autoname name stays synced to field on rename** — if name is derived from a field, the name does not drift when the field changes via save (it is recomputed/kept) (`test_field_autoname_name_sync`).
3. **child-table autoname honored** — a child DocType with `autoname="field:some_fieldname"` names its rows from that field, even when inserted as part of a parent save; and changing the field on an existing child row does NOT rename it (`test_child_table_naming`).
4. **`format:` autoname** — replace every `{braced}` param (fields, `MM`/`YY`/`WW`/…, and `{#####}` series); `-.#####` is normalized to `.-.#####`; if a bare `#` series remains after substitution it is run (`test_format_autoname`, `_format_autoname`).
5. **`format:` converts datetime/date/time field values to strings** for naming (`test_format_autoname_for_datetime_field`).
6. **`WW` = consecutive ISO week number** via `determine_consecutive_week_number` (ISO `%V` with year-boundary fixups: Jan & week≥52 → "00"; Dec & week≤1 → "53") (`test_format_autoname_for_consecutive_week_number`, `test_determine_consecutive_week_number`).
7. **Expression autoname** (`autoname` contains `#` but no rule prefix): substitute `{braced}` params, normalize `(?<!\.)(-\.#+)` → `.\1`, then run as a naming series. Patterns `{a}-{b}-.#####` and `{a}.-.{b}.-.#####` both produce `a-b-00001` (`test_expression_autoname_*`).
8. **`naming_series:` autoname** — series string = `doc.naming_series` else first non-empty option of the `naming_series` field; append `.#####` if no `#`; run series (`set_name_by_naming_series`, `get_default_naming_series`).
9. **`NamingSeries.get_prefix()`** — `SINV-.YY.-.####` → `SINV-22-`; `SINV` → `SINV`; `SINV-.` → `SINV-` (`test_naming_series_prefix`).
10. **`NamingSeries.validate()`** — must contain a dot; only `[\w\- \/.#{}]` allowed; if `#` present then `.#` must be present (`test_naming_series_validation`): `$INV-`, `WINDOWS\NAMING` are invalid.
11. **naming using doc fields in series** — `KOOH-.{webhook_docevent}.` → `KOOH-on_update…` (`test_naming_using_fields`).
12. **empty part / duplicate dots tolerated** — `KOOH-..{f}.-.####` still resolves (`test_naming_with_empty_part`).
13. **unsupported field value type (dict) → skipped** (only int/str/datetime/date/time/timedelta accepted) — `KOOH-..{dict}.-.####` → starts `KOOH-` (`test_naming_with_unsupported_part`).
14. **empty field value → empty part** — `KOOH-.{request_structure}.-…` → `KOOH---…` (`test_naming_with_empty_field`).
15. **`hash` autoname** — `(_get_timestamp_prefix() + random)[:10]`, 10 chars, roughly time-sequential (`test_hash_naming_is_roughly_sequential`); in_import allows caller-supplied name + collisions retried (`test_hash_collision`).
16. **`UUID` autoname** — auto: `str(uuid7())` (version 7); accepts a caller-supplied `uuid.UUID`/uuid4/uuid7/valid-string; invalid string → `InvalidUUIDValue`; name column type is `uuid` (`test_uuid_naming`).
17. **`autoincrement`** — name is the next DB sequence integer; consecutive inserts → 1,2,3,…; name returned/stored as **int** (`test_autoincremented_naming`).
18. **`prompt` autoname** — caller must supply name (`__newname`); none → throw "Please set the document name" (`test_naming_validations` case relies on prompt for Tag).
19. **`getseries(key, digits)`** — atomic per-prefix counter in `tabSeries`, zero-padded (`getseries`, used everywhere).
20. **`revert_series_if_last(key, name)`** — on rollback/failed-insert, decrement `tabSeries.current` iff this name was the last allocated; handles `.#`-in-hashes, `.#`-in-prefix, `####.-suffix`, and empty-prefix forms (`test_revert_series`).
21. **`append_number_if_name_exists`** — `Bottle` → `Bottle-1` → `Bottle-2`; custom field+separator → `Bottle_1` (`test_append_number_if_name_exists`).
22. **amended/cancelled naming** — cancel keeps name; amended copy → `<orig>-1`, and re-cancel keeps it (`test_naming_for_cancelled_and_amended_doc`, `_set_amended_name`).
23. **custom parser hooks** (`naming_series_variables`) — a series part like `.PM.` resolved via a hooked function (`test_custom_parser`, `has_custom_parser`).
24. **`validate_name`** — reject empty ("No Name Specified"), `New <doctype>` prefix, `name == doctype` (except DocType), and `<`/`>` special chars (`test_naming_validations`).

### PARTIAL
- **B5 `format:` datetime field → string** (`test_format_autoname_for_datetime_field`): ferro `cstr` (`naming.rs:17-24`) stringifies a JSON value; over REST a date field arrives already as a JSON string, so the field-substitution path yields the same text. PARTIAL because ferro never receives Python date/datetime/time objects (no in-process path), and `cstr` of a non-string JSON number/bool would produce a different form than Frappe's `cstr(datetime)`. For the REST contract it matches; for the in-process contract it is not exercised.
- **B17 `autoincrement`** (`test_autoincremented_naming`): ferro `next_autoincrement` (`naming.rs:223-236`) computes `MAX(CAST(name AS INTEGER))+1` and returns it as a **string** (`naming.rs:235`). Frappe uses a real DB sequence and returns/stores an **int**. The numeric value is correct and consecutive (1,2,3…), but (a) the JSON/stored representation is a string not an int, and (b) `MAX+1` is not gap-safe if a row is deleted then re-inserted (a sequence would not reuse), and (c) requires a pre-existing INTEGER-shaped name column. The test asserts `name == i` (int equality) — over REST ferro returns `"1"`. Substantive value MATCH, type/semantics PARTIAL.
- **B23 custom parser hooks** (`test_custom_parser`): ferro has no `naming_series_variables` hook mechanism (no Python hooks at all). A series part `.PM.` would be treated as a literal `PM` (`eval_part` fallthrough `naming.rs:204`) instead of being resolved by the hooked function. For a pure-Rust runtime with no app Python this is unreachable, but the behavior diverges → PARTIAL (literal vs hooked value).

### GAP
- **GAP-child (High)** — *child-table autoname not honored.* `orm.rs:711` `insert_children` ALWAYS assigns `let cname = util::random_name();` for every child row, ignoring the child DocType's `autoname`. Frappe runs the full `set_new_name` for each child, so a child with `autoname="field:some_fieldname"` is named from that field, and is NOT renamed when the field later changes. ferro fails `test_child_table_naming` (asserts `doc.table_with_naming[0].name == name` and stability across edits). **Fix location:** `orm.rs:711`. **Sketch:** before building child cols, if `item.name` is absent/empty, load the child DocType `Meta` (cache by `child_dt`) and call `naming::resolve_name(con, &child_meta, obj)` instead of `random_name()`; respect an explicitly-supplied child `name` for the no-rename-on-edit guarantee (on update, keep existing child name rather than regenerating).
- **GAP-WW (High)** — *`WW` week number is wrong.* `naming.rs:197` computes `(day_of_year+6)/7`, a crude approximation, NOT ISO-8601 consecutive week. Measured divergences vs Frappe: 2021-01-01 (Frappe 00 / ferro 01), 2021-12-31 (52/53), **and today 2026-06-10 (Frappe 24 / ferro 23)** — so any live `WW` naming is wrong, corrupting `tabSeries` keys vs a CPython worker. Breaks `test_format_autoname_for_consecutive_week_number` and the `determine_consecutive_week_number` assertions. **Fix location:** `naming.rs:197` (`eval_part` `"WW"` arm). **Sketch:** implement `determine_consecutive_week_number`: compute ISO week (Howard-Hinnant: ISO week = `(ordinal - weekday + 10)/7` clamped, or derive from `day_of_year` + Jan-1 weekday), 2-digit; then apply the boundary fixups: if `month==1 && isoweek>=52 → "00"`; if `month==12 && isoweek<=1 → "53"`. Add a `util::iso_week(y,m,d)` helper.
- **GAP-ts (Low)** — *`timestamp` part drops microseconds.* `naming.rs:198` formats `YYYY-MM-DD HH:MM:SS` (seconds), Frappe uses `str(now_datetime())` = `...:SS.ffffff` (microseconds). Names like `Log on 2026-06-10 05:40:52` vs Frappe `Log on 2026-06-10 05:40:52.123456`. Affects any `{timestamp}` format/series doctype (Console Log, etc.); also raises collision risk under second-granularity. Not directly asserted by a test (no test pins microsecond format) but is a real divergence. **Fix location:** `naming.rs:198` + `util::now_civil` (which only returns down to seconds). **Sketch:** extend `now_civil` to also return microseconds (the `SystemTime` duration already has nanos: `dur.subsec_micros()`), and append `.{:06}` in the `timestamp` arm.
- **GAP-revert (Med)** — *no `revert_series_if_last`.* ferro has no series-revert: on a failed/rolled-back insert (or amended-doc revert) the `tabSeries.current` is never decremented, so the next allocation skips a number (gaps in the series) and `current` drifts above the highest live name. Frappe decrements iff the failed name was the last allocated (`test_revert_series`, 5 cases incl. `.#`-in-hashes and empty-prefix forms). Because ferro's insert advances the counter inside the txn (`getseries` at `naming.rs:212`), a rollback of the txn DOES roll back the UPSERT — so for the *single-statement-failure* case ferro is actually fine via txn atomicity. The gap is the EXPLICIT-revert API surface and the amended-doc path. **Fix location:** new fn in `naming.rs` + call sites. **Sketch:** add `revert_series_if_last(con, key, name)` mirroring naming.py:441 (rsplit on last `.`, regex `#+`, recompute prefix via `parse_naming_series`, decrement iff `current == count`); call it where ferro intentionally discards an allocated name. Lower urgency given txn-atomic counter, but needed for fidelity of the public function and amended naming.
- **GAP-append (Med)** — *no `append_number_if_name_exists`.* ferro never appends `-1/-2` when a name collides; it returns a DuplicateEntryError instead (verified: second `Currency FerroDup` → 409). Frappe's `append_number_if_name_exists` produces `Bottle-1`, `Bottle-2`, `Name_1`, used by rename, amended naming, and some controllers (`test_append_number_if_name_exists`). **Fix location:** new fn in `naming.rs`. **Sketch:** add `append_number_if_name_exists(con, doctype, value, fieldname="name", sep="-")`: if `EXISTS`, query `SELECT <field> FROM tab<dt> WHERE <field> REGEXP '^<value><sep>\d+$' ORDER BY length DESC, <field> DESC LIMIT 1`, parse trailing number +1 (SQLite has no REGEXP by default — use `GLOB`/LIKE-prefilter + Rust-side regex/parse). Wire into amended naming (GAP-amend).
- **GAP-amend (Med)** — *amended/cancelled naming not implemented.* ferro has no `amended_from` handling; an amended copy would get a fresh hash/series name, not `<orig>-1`, and the cancel-keeps-name guarantee isn't expressed (ferro has no submit/cancel/docstatus-transition naming logic). Frappe `_set_amended_name` → `<orig>-1`, `<orig>-2`, governed by Document Naming Settings `default_amend_naming` (`test_naming_for_cancelled_and_amended_doc`). Submit/cancel themselves are a broader subsystem gap; here only the naming aspect is in scope. **Fix location:** `naming.rs:resolve_name` (add an early `amended_from` branch before the autoname switch). **Sketch:** if `data.amended_from` present and amend rule != "Default Naming", compute `am_prefix`/`am_id` from `amended_from` (check whether `amended_from` itself has an `amended_from` to decide split point) and set name = `am_prefix-am_id`; needs `append_number_if_name_exists`-style collision handling. Depends on submit/cancel existing to be fully testable.
- **GAP-uuid-validate (Low)** — *invalid UUID not rejected.* For a `UUID`-autoname doctype, a caller-supplied non-UUID `name` (e.g. `"XYZ"`) is accepted verbatim because explicit `name` wins at `naming.rs:34-38` with no UUID validation; Frappe raises `InvalidUUIDValue` (`test_uuid_naming` last assertion). Also ferro does not enforce the `uuid` column type. **Fix location:** `naming.rs:34-38` + the `lower == "uuid"` arm. **Sketch:** when `meta.autoname == "UUID"` and a `name` is supplied, parse/validate it as a UUID (8-4-4-4-12 hex) and Validation-error on failure before `validate_name`.
- **GAP-validate-int (Low)** — *integer `name` not handled.* Frappe `validate_name` accepts an int name only for autoincrement doctypes (sets sequence) and rejects int names otherwise (`Invalid name type (integer) for varchar name column`, raised as `NameError`). ferro's `validate_name` (`naming.rs:239`) only handles `&str`; an int name arriving via JSON would be coerced earlier/handled inconsistently. Minor for REST (clients send strings) but a fidelity gap. **Fix location:** `naming.rs:239` + caller `resolve_name` name extraction (`naming.rs:34`, only reads `as_str()`, so a JSON-number `name` is silently ignored → falls through to autoname). **Sketch:** detect JSON-number `name`, route to autoincrement-or-reject as Frappe does.

### Undocumented ferro behavior (divergences not covered by a test)
- **Error-envelope / HTTP status for naming `ValidationError`:** ferro returns **HTTP 417** for naming Validation errors (special-char, prompt-missing, name==doctype, "New …"), and 409 for duplicate. Frappe's REST returns these as `ValidationError`/`NameError` with its own status mapping (often 417 for ValidationError, 409 for duplicate). The duplicate path matched (409); the NameError cases come back as `exc_type:"ValidationError"` not `"NameError"` — ferro collapses `NameError` into `ValidationError` (it has no separate NameError type). Tests assert `frappe.NameError` vs `frappe.ValidationError` in-process; over REST the `exc_type` string differs.
- **Required-field message uses fieldname, not label:** empty `field:` → ferro `"currency_name is required"`; Frappe `_("{0} is required").format(meta.get_label(fieldname))` → `"Currency Name is required"` (label). `naming.rs:57`.
- **`autoname == "autoname"` literal treated as hash:** `naming.rs:50` maps `lower=="autoname"` to `random_name()`. Frappe has no such special case — `"autoname"` is not a recognized rule and would be treated as an Expression/literal (no `#` → falls through to hash via the final fallback anyway, so end result coincidentally matches, but for a different reason). Harmless but undocumented.
- **`#` series allocation eagerness:** ferro allocates the `tabSeries` counter inside `parse_naming_series` even for `format:`/Expression names that may later be rejected by `validate_name` (validation runs AFTER the counter is bumped, `naming.rs:79`). Frappe validates after too, but ferro's lack of `revert_series_if_last` (GAP-revert) means a name rejected by `validate_name` after the counter bump leaves the counter advanced (the surrounding txn rolls it back only if the whole insert aborts; a caught-and-handled validation could leak). Edge case.
- **`naming_series_value` errors "Naming Series mandatory"** when neither payload nor first docfield option exists — matches Frappe's `set_name_by_naming_series` throw; good, but ferro reaches it only for explicit `naming_series:` rule, while Frappe also has the `get_default_naming_series` empty-string-skipping nuance (ferro's `lines().find(non-empty)` correctly skips the leading empty option Frappe uses to blank the form). Confirmed MATCH on that nuance (`naming.rs:92`).
